# 資金繰りの見通し

## 本家

- 名前：Anthropic 公式 `small-business` プラグインの `cash-flow-snapshot`（knowledge-work-plugins、Apache-2.0）
- 原文：https://github.com/anthropics/knowledge-work-plugins/blob/main/small-business/skills/cash-flow-snapshot/SKILL.md
- 中身：データ元を確かめる → 残高・売掛・買掛・固定費を集める → 取引先ごとの入金の遅れを計算する → 30／60／90日の見通しと幅を出す → 名前の付いたリスクを5つまで挙げる → チャットの要約と表を出す。開始残高は推測しない

## 本家の読み方

1. `small-business:cash-flow-snapshot` が入っていれば、それを呼んで手順に従う
2. 入っていなければ、上の原文と、同じフォルダの `reference/` を開いて読み、その手順に従う
3. 原文が開けなければ、その旨を伝えて止まる

## 0. 設定を読む

🧭 AI設定ページの接続表から読む。

| 論理名 | 中身 |
| --- | --- |
| 会計 | 会計ソフト（例：freee）。口座残高・未決済の取引・取引先 |
| `cash_plan` | 資金繰り表（スプレッドシート）。あれば**正本**として扱う |
| `finance_log` | 経営ログ（見通しを残す先） |
| `loans` | 借入（返済の予定） |
| `applications` | 補助金・助成金の申請（入金の予定） |

自分ルールのこのスキルの欄（決算月、消費税の課税の方式、繁忙期、季節雇用の時期など）も読む。

## 調整（本家と違うところだけ）

### 1. データ元を日本のものに

- 本家の「台帳（QuickBooks など）」は、日本の会計ソフト（freee など）に読み替える。口座の残高と日付、未決済の売掛・買掛、繰り返しの支払いを取る
- 会計ソフトのコネクタが無ければ、本家の CSV の手順を使う
- **資金繰り表があれば、そちらの予定を優先**し、会計ソフトの実績で答え合わせをする。食い違いは一覧で示す（どちらかを勝手に直さない）

### 2. 期間を1年に広げる

ワインは、春〜秋に栽培の支出が続き、収穫・仕込みで大きく出て、売上はボトルが売れる翌年以降に来る。30／60／90日だけでは山と谷が見えない。

- 本家の30／60／90日に加えて、**12か月の月ごとの見通し**を出す
- 月ごとの最低残高と、その月を出す

### 3. 日本の決まった支払いを入れる

本家の固定費に加えて、日付の決まった支払いを入れる。日付と金額は、会計ソフト・過去の実績・通知書から取り、推測しない。分からないものは「未確認」として表に残す。

- 社会保険料（毎月）、労働保険の年度更新
- 源泉所得税（毎月、または納期の特例で年2回）、住民税の特別徴収
- 消費税（確定申告と中間納付）、法人税等（確定と中間）
- 酒税（製造者の場合。申告と納付の時期は自分ルールと tank の設定に従う）
- 固定資産税（年4回）
- 借入の返済（`loans`）、リース

### 4. 補助金は「立て替え」として扱う

補助金・助成金は多くが精算払い（先に払い、実績報告のあとに入る）。

- 交付決定済みの事業は、支払いの月に全額の支出、入金は「実績報告＋審査の期間」後の月に置く
- 入金の時期は確定でなければ幅を持たせ、見通しの低い側では入金に入れない
- grants の grant-support から渡された予定があれば使う

### 5. 季節の波をリスクとして名指しする

本家の「名前の付いたリスク」に、ワイン生産者に多いものを足す：収穫・仕込みの月の資材と人件費の山／瓶詰め前の資材（瓶・コルク・ラベル）のまとめ買い／在庫として眠る期間／補助金の立て替え／税の中間納付が重なる月。

### 6. 出し方

- チャット：最低残高の月と金額、足りなくなる見込みがあればその月と額、上位のリスク
- 表：本家の形に加えて12か月の月ごと。資金繰り表があれば、書き込む前に案を見せて承認を取る（書き込むのは利用者の表なので）
- `finance_log` に、見通しの要約と前提を1件残す（承認を取ってから）
