# 図解の作り方

**図は飾りではなく主張。** 文字を消しても形だけで「何が何を含み、何が何につながり、どちらへ流れるか」が伝わる図にする。文字をそれらしく箱に入れて並べただけの図は、文章より読みにくい。

この手順は、櫻田潤『図で考える。シンプルになる。』の7つの図、Dan Roamの「6つの見方」、Engelhardtの図の文法（位置・まとまり・仕切り・並び・つなぎ・入れ子・重ね）、Mayerのマルチメディア学習の原則（余分を除く・構造を目立たせる・ラベルを近くに置く）、海外の図解スキル（excalidraw-diagram、diagram-design）の考え方を、Notionの資料向けにまとめたもの。根拠は `references/sources.md`。

## 手順

### 1. 図にするかを決める

次のどれにも当たらないなら、図にしない（文か表で書く）。

- 要素どうしの**関係**（含む・流れる・やり取り・重なり・層）が主役で、文で読むと頭の中で組み立て直す必要がある
- 全体の中での**位置**を見せたい（「いまどこの話か」）
- 量や推移を比べる（グラフ）

並列の項目を並べるだけなら箇条書き、同じ項目で比べるなら表。箱が1つなら、それは文。

### 2. 構造メモを用意する

structure-reading の構造メモ（まとまり・関係の種類・本筋）が無ければ先に作る。**図は構造メモの関係を写すもの**で、元の文章を写すものではない。

### 3. 問いを1つに絞る

1枚の図が答える問いを1つだけ決め、図のタイトルにする。問いが2つあるなら図を2枚に分ける。

| 問い（Roamの6つの見方） | 合う型 |
| --- | --- |
| 何が・誰が（登場するものと、その関係） | 交換の図、関係図 |
| どれだけ | グラフ |
| どこに（全体の中の位置・分類） | ツリー、入れ子、マトリクス |
| いつ・どの順で | 段取り、タイムライン |
| どうやって（仕組み） | フロー、層 |
| なぜ | 深掘り（なぜの連鎖）、因果、ループ |

### 4. 型を選ぶ

構造メモの関係の種類から型を選ぶ。型ごとの描き方は `references/patterns.md`。

- 含む → ツリー／入れ子の箱（入れ子は2段まで。3段以上はツリーにする）
- 順序 → 段取り（左→右、上→下）
- やり取り → 交換（登場するものを離して置き、**矢印に渡すものを書く**）
- 対比・位置づけ → 2軸の比較／表
- 重なり → ベン図（円は3つまで）
- 層 → 積み重ね（下が土台）
- 循環 → ループ
- 1枚に関係が2種類までなら1つの図にしてよい（例：入れ子の中に順序）。3種類以上は図を分ける

### 5. 主役と視線の道を決める

- **主役を1つ**決め、いちばん大きく・いちばん余白を取る。全部を同じ大きさの箱にしない
- 読む順に置く（左上 → 右下、または上 → 下）。読み始めの場所が一目で分かるようにする
- 要素は1枚に**7つ前後まで**。多いならまとまりで畳み、中身は本文やサブページで見せる

### 6. 描く（守ること）

- **関係は必ず線か入れ子で表す**。近くに置いただけでは関係にならない。矢印には何が流れるか（「配る」「承認」）を書く
- **箱は意味があるときだけ**。まとまり・境界を示すときに使い、ただのラベルは箱に入れない。同じ形の箱を格子状に並べない
- **文字を減らす**。1要素は名前＋短い説明1行まで。説明が要るなら図の外の本文で書く
- **ラベルは指すものの真横に**。凡例を見に行かせない
- **色は意味に使う**。色は3つまで、強調色は1つ。同じ意味には同じ色
- **文字は小さくしない**：本文13px以上、補足でも12px以上
- 線の種類は2つまで（実線＝流れ・つながり、点線＝参照・弱いつながり）

### 7. 描き方を選ぶ（Notion）

| 描き方 | 向いている図 | 注意 |
| --- | --- | --- |
| HTMLブロック | 入れ子・層・配置そのものに意味がある全体像 | 幅約700pxで読めること。明るい表示と暗い表示の両方で読めること。雛形は `references/notion-html.md` |
| Mermaid | 流れ図・順序・ツリーなど、線でつなぐ図 | ノードは10個前後まで。ラベルは短く |
| 表 | 同じ項目で比べる・対応づける | 図にしない |

### 8. 実物で点検する（省略しない）

描いたら、**実際に表示される幅（Notionなら約700px）で、明るい表示と暗い表示の両方の画像を撮って見る**。そのうえで次を確かめ、直して撮り直す（2〜3回はふつう）。

1. **形だけテスト**：文字をぼかしても、何が何を含み、どちらへ流れるかが分かるか
2. **問いに答えているか**：タイトルの問いの答えが、図を見て10秒で言えるか
3. **構造メモと照合**：メモにある関係が全部図にあるか。メモに無い関係を図が言っていないか
4. **見た目の欠陥**：文字の折り返し・はみ出し・重なり、矢印の行き先違い、小さすぎる文字、詰まりすぎ
5. **本文との重複**：図が言っていることを本文が繰り返していないか

## やってはいけないこと（実際に起きた失敗）

- 同じ大きさの箱を格子状に並べ、文字を詰めただけの図。関係が見えず、文章より読みにくい
- 10.5pxのような小さな補足文字を多用する
- 矢印が飾りで、何が流れるかが書いていない
- 作った幅（720px）と表示される幅（Notionの約700px）が違い、矢印の並びが折り返して崩れた
- 3段・4段の入れ子に、関係の種類を3つ以上詰め込む
