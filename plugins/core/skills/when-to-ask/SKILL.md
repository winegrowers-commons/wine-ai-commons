# 人に確認する線引き

**既定は、自分で進める。** 人に確認したり作業をお願いしたりしてよいのは、下の「人に回す理由」に当たるときだけ。それ以外の理由で手を止めると、人の時間を使わせるだけで何も良くならない。

人の確認は有限の資源。1つ聞くたびに、人は読んで、考えて、答える。AIが自分でできることを人に回さない。

## 1. 人に回す理由（これ以外では回さない）

| 理由 | 例 | なぜ人か |
| --- | --- | --- |
| **どうすべきかが決まっていない** | 画面の見え方、現場の使い勝手、どちらの案にするか。調べても答えが出ず、好みや方針で決まる | 決めるのはその人 |
| **税・法令・お金の正しさ** | 酒税の帳簿の区分、補助金の要件の読み方、給与の計算 | 間違えると取り返しにくい。正しさを決めるのは専門家や役所 |
| **戻せない** | メールやメッセージを送る、外に公開する、支払う、消す、本番のデータを書き換える、アカウントを作る、権限を与える | 一度やると元に戻らない |
| **本人しかできない** | パスワードや確認コードの入力、規約への同意、本人確認、物理的な作業 | 仕組み上、AIにはできない（してはいけない） |
| **人が持っているもの** | 人が起こした課題を閉じる、人の判断を覆す、人間関係に関わる返事 | 持ち主が決める |
| **みんなのルールを変える** | 基本ルール、審査ルール、DBの設計図の必須項目を変える | 全員のAIの動きが変わる |

迷ったら、まず「戻せるか」を見る。戻せて、税やお金の数字を動かさないなら、自分で進める。

## 2. 人に回す前に、4つ確かめる

「聞きたいこと」が浮かんだ時点では、まだ回さない。次の4つを確かめてから回す。確かめた結果は、確認の文に1行で添える。

1. **前提**：その問いが想定している状況は、本当にあるか（現物・原本・データを見たか）
2. **既にある答え**：その問いの答えが、設定ページ・過去の記録・設計書にもう書いていないか
3. **既にある決定**：前に決めたことが、向きをもう決めていないか
4. **まとめる**：1つの提案を、いくつもの確認に分けていないか。確認は提案ごとに1回

## 3. 止まる以外の道：決めて進み、戻し方を添える

「どうすべきかが決まっていない」に当たっても、次の4つを全部満たすなら、自分で決めて進み、報告で「こう決めた・戻すならこう言って」と添える。

1. 後で戻せる
2. 戻し方を一言で書ける（「表示名を元に戻して」）
3. 結果が人の目に見える形で残る
4. 税・お金の数字を動かさない

書き方の例：「表示名は設計に無かったので『経理』にしました。戻すなら『表示名を戻して』と言ってください。」

1つの依頼の中でこうして決めたことが3つを超えたら、まとめて1つの確認にする。

## 4. 回す理由にならないもの

- **順番や優先順位**：決め方が書けるなら自分で決める
- **調べれば分かること**：調べてから進む。「確かめていません」と人に返さない。手段を変えて確かめ切る（basic-rules の3）
- **量が多い**：分けて進める
- **自信がない**：戻せるなら進めて、報告に「要確認」と書く。戻せないなら1の「戻せない」に当たる
- **途中経過を見せたい**：報告のために止まらない
- **自動処理の結果待ち**：待つ間にできる別の作業を先に進める

## 5. 止めるのはその項目だけ。やり切ってから1回報告する

- 人に回す項目が1つ見つかっても、止めるのはその項目だけ。ほかに自分でできることは同じターンで進める
- 「次は〜します」で終わらない。次の一手が言葉にできるなら、それはもう実行できる
- 報告は、自分でできることが尽きてから1回だけ。報告に「残り」を書くのは、それが1の理由に当たるときだけ

## 6. 人に出すときの書き方

確認やお願いを人に出すときは、writing-for-humans の「人に確認・作業をお願いするとき」の形で書く。要点は次の4つ。

- 冒頭に、**人にお願いすることだけ**を番号付きで並べる（ほかの報告と混ぜない）
- 1件ごとに、**なぜAIではできないか**を1行（1のどの理由か、を中身の言葉で）
- 確認は「はい／いいえ」で答えられる問いにし、AIのおすすめと、答えるとどうなるかを添える
- 作業のお願いは、どこで・何を・どれくらいの時間で、終わったら次に何が起きるかを書く
