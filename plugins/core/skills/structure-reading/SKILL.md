# 情報の構造を読み取る

図や文章が分かりにくくなる原因の多くは見せ方ではなく、**作る前に情報どうしの関係をつかんでいないこと**にある。このスキルは、作る前の「構造メモ」を作る。図や文章はこのメモから作る。

手順は川喜田二郎のKJ法（ラベル作り → グループ編成 → 図解化 → 文章化）と、文章の reverse outline（各段落の要旨を抜き出して並べる）を、AIが1人で回せる形にしたもの。

## 手順

### 1. 何のための整理かを決める

- 読み手（既定は writing-for-humans の「AIに詳しい高校生」）
- 読み終わったら読み手が何を分かり、何ができるか（中心の命題）を1文で仮置きする。後の手順で直してよい

### 2. 要素を1つずつ書き出す（単位化）

- 元の資料から、意味のまとまりを**1要素1文**で書き出す。見出しの名前ではなく、本文が実際に言っていることを書く
- 抽象的にまとめすぎない。「データは分ける」でなく「事業データはGitHubに入れず、各自のNotionに置く」
- 数字・固有名・条件は落とさない

### 3. 近いものを集め、まとまりに名前を付ける（グループ編成）

- 似ているものではなく、**同じことを言おうとしているもの**を集める
- 集めたまとまりに、中身を1文で言い切る名前（表札）を付ける。「その他」「概要」のような名前は付けない
- 小さいまとまり → 大きいまとまりへ、2〜3段まで。これが**包含関係**（何が何に含まれるか）になる
- どこにも入らない要素は無理に入れず、「はぐれ」として残す。本筋に要らないなら捨てる候補

### 4. まとまりどうしの関係に名前を付ける

包含（含む）以外の関係を、**種類つきで**書く。矢印を引くだけでは関係にならない。

| 関係の種類 | 書き方の例 | 図にするときの型（diagram） |
| --- | --- | --- |
| 含む・分類 | AはB・C・Dからなる | ツリー、入れ子の箱 |
| 順序・手順 | A → B → C | 段取り（ステップ）、タイムライン |
| 因果・理由 | AだからB | 深掘り（なぜの連鎖）、因果の矢印 |
| 循環 | A → B → C → A | ループ |
| 対比・位置づけ | AとBを軸で比べる | 比較（2軸・表） |
| やり取り | AがBにXを渡し、BがAにYを返す | 交換（矢印にラベル） |
| 重なり | AとBの両方に当てはまるもの | 重なり（ベン図） |
| 層・段階 | 下の層の上に上の層が乗る | 積み重ね（ピラミッド・層） |
| 対応・割り当て | 行の項目 × 列の項目 | 表・マトリクス |

### 5. 本筋と補足を分ける

各要素・まとまりに、中心の命題に対する役割を付ける：**本筋**（命題を直接支える）／**前提**（読む前に要る）／**補足**（知りたい人だけ）／**余分**（なくても困らない）。補足と余分は、本文でなくトグル・サブページ・削除の候補になる（writing-for-humans の「詳細の置き場」）。

### 6. ずれを洗う

- **重複**：同じことを2か所以上で言っていないか。同じ分類を本文と表で二重に書いていないか
- **矛盾**：数字・名前・決定が場所によって違わないか
- **古さ**：変わったはずの案・数字が残っていないか
- **名前のぶれ**：1つのものを2つの名前で呼んでいないか

## 出力：構造メモ

```
読み手：
中心の命題（1文）：
まとまり（包含のツリー）：
  - 表札1：要素… 
    - 表札1-1：要素…
  - 表札2：…
まとまりどうしの関係：
  - 表札1 →（順序）表札2
  - 表札2 ⇄（やり取り：何を渡すか）表札3
本筋／前提／補足／余分：
ずれ（重複・矛盾・古さ・名前のぶれ）：
図にすべきもの：（関係が主役で、文だと想像しにくいもの。1枚につき問い1つ）
表にすべきもの：（同じ項目で比べるもの）
文で十分なもの：
```

この構造メモを人に見せる必要はない。図や文章を作る前の下ごしらえとして使い、作り終わったら、図と文章が構造メモの関係を全部表せているかの照合に使う。
