# 補助金・助成金の伴走

## 本家

- 名前：Anthropic 公式 `small-business` プラグインの `grant-rfp-writer`（knowledge-work-plugins、Apache-2.0）
- 原文：https://github.com/anthropics/knowledge-work-plugins/blob/main/small-business/skills/grant-rfp-writer/SKILL.md
- 中身：組織を一度理解する → 合う機会を探す → **書く前に出す／出さないを決める**（資格→必須要件→提出の形式→実行できるか→勝ち目）→ 要件の対応表を先に作る → 実際の材料から下書き（捏造しない。分からない所は空欄と質問で残す）→ 提出は本人が決める → 締切と採択後の義務を追う

## 本家の読み方

1. `small-business:grant-rfp-writer` が入っていれば、それを呼んで手順に従う
2. 入っていなければ、上の原文と、同じフォルダの `reference/` を開いて読み、その手順に従う
3. 原文が開けなければ、その旨を伝えて止まる

## 0. 設定を読む

🧭 AI設定ページから、接続表の `applications`（申請）、`subsidy_assets`（補助金で取得した財産）と、自分ルールのこのスキルの欄（法人の形、認定農業者・認定新規就農者などの認定、所在地、従業員の数、過去の採択）を読む。

## 調整（本家と違うところだけ）

### 1. 対象者の確認を飛ばす

本家は非営利・政府調達向けで、営利の会社には最初に確認する。農業法人・個人の生産者は日本の補助金の主な対象なので、**この確認はせずにそのまま進める。**

### 2. 探す先を日本のものに

本家の SAM.gov などの代わりに、次を探す。

- 国：jGrants（電子申請）、ミラサポplus、農林水産省（担い手・6次産業化・輸出・スマート農業など）、経済産業省・中小企業庁（ものづくり・持続化・IT導入など）、厚生労働省の雇用関係の助成金
- 都道府県・市町村の農業・商工の補助（自分の所在地）
- 日本政策金融公庫などの制度融資（補助金ではないが、資金繰りと一緒に検討する）
- grants プラグインの**制度カタログ**（`catalog/`）。ほかの生産者が書いた「つまずいた点」「併用できた組み合わせ」がある

カタログの情報は、使う前に必ず公式の公募要領で最新を確かめる。違っていればカタログを直す提案を出す（core の propose-change）。

### 3. 出す／出さないの判断に日本の論点を足す

本家の5つの確認に加えて：

- **交付決定の前に着手していないか**（発注・契約・支払いを決定前にすると対象外になる制度が多い）
- 見積もりの取り方（相見積もりの要否）
- ほかの補助金との**併用の可否**、同じ経費の重複
- 補助率と上限、**自己負担と立て替えの額**（精算払いが多い）→ finance の cash-flow で資金繰りに当てる
- 交付後の義務：実績報告、**財産の処分制限の期間**（期間内の売却・転用・廃棄には承認が要る）、事業の効果の報告
- 労務の助成金は、就業規則・雇用契約・出勤簿・賃金台帳が要件を満たしているか（labor の記録と照らす）

### 4. 下書きは本家どおり捏造しない

実績・数値・取引先・計画の数字が無いところは空欄にし、利用者に聞く質問を添える。公募要領の審査項目の配点に合わせて書く量を配る。

### 5. 交付後の追跡

- 締切・実績報告・効果の報告・処分制限の期間を `applications` に入れ、カレンダーにも余裕を持って入れる（入れる前に確かめる）
- 補助金で買った機械・設備は `subsidy_assets` に入れ、処分制限の終わる日を書く。equipment の台帳とつなぐ
- 圧縮記帳などの会計処理は accounting に渡す

### 6. 制度カタログを育てる

申請が終わったら、事業データを抜いて「つまずいた点」「審査で効いたこと」「併用できた・できなかった組み合わせ」を、カタログへの提案にする（`catalog/README.md` の形）。

## 本家とぶつかったとき

本家の新しい版がこの調整と食い違ったら、調整に従い、その旨を一言書く。調整の見直しが要りそうなら、core の propose-change で提案する。
