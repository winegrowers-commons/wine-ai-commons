# 参考文献の登録：細かい仕様

## パート1：書誌の値（プロパティ）

| プロパティ | 型 | 書き方 |
| --- | --- | --- |
| 書籍名・記事名 | タイトル | 原題のまま。翻訳しない |
| 形態 | 選択 | 書籍／雑誌／Webページ／Blog／調査報告書／学術誌／セミナー／その他 から1つ |
| 雑誌名・Webサイト名 | 選択 | 既存の選択肢と完全一致を優先。無ければ `新規：〇〇` |
| 発行年 | 数値 | 西暦4桁 |
| URL | URL | DOIがあればDOI（`https://doi.org/…`） |
| 引用ページ | テキスト | 呼び出し元のページをメンションで。利用者が足したページも |
| 要約 | テキスト | 日本語2〜3行。「何が分かったか」を主語にする。書誌だけの登録では `出版社紹介文より：「…」` の引用、無ければ空 |
| 著者 | リレーション | 氏名を並べる。著者DBへのひも付けは利用者が後でする |
| 備考 | テキスト | 原典に書かれていないことの置き場（登録時の文脈、AIの評価の観点、自社への示唆、関連ページ、重複の疑い） |
| タグ | 複数選択 | 空。利用者が後で付ける |
| 添付ファイル | ファイル | PDFは利用者が手で添付する |
| Read later | チェック | いいえ |
| ページアイコン | — | `icons/book-closed_red` に固定 |

取れなかった項目は空にし、注釈にその理由を書く。プロパティ名が自分のDBと違う場合は、🧭 AI設定ページの接続表の対応に従う。

## パート2：ページ本文（「AI要約」トグルの中）

順番は「注釈 → 要約 → 構造化ノート」。

### 要約

- 日本語、800字が目安。短くてよく、膨らませない
- 必ず段落に分ける。1つのべた書きは禁止。短い小見出し（H3か太字）を付けてよい
- 論文：品種、試験地・気候、主な数値の結果、実務上の結論を必ず入れる
- Web記事：主張の要旨、根拠のデータ、実務上のポイント
- 「〜を調査した」より「何が分かったか」を主語にする
- 著者自身が実務への示唆を書いているときだけ、最後に付ける。AIが外から補わない

### 構造化ノート

文献の種類でテンプレートを変える。合わなければ形を変えてよい。

### 注釈

- ソース情報：ファイル名かURL、原題、著者、発行年、掲載誌・サイト名
- 入力の種類：PDF添付／URL読み込み／既存ページのPDF／本文の抜粋
- 読み取りにくかった箇所と、その扱い（推測で補ったならその中身）
- 取れなかったプロパティと理由
- 表にできなかった図表の説明
- 訳語で迷った箇所
- 雑誌名・サイト名の新しい選択肢の候補
- 処理の前の確認の結果と、確かめられなかったこと
- そのほか（複数の論文が1つのPDFになっている、付録の有無、アクセス制限など）

## パート3：登録ログ（ページ末尾、トグルの外）

```
## 登録ログ
- YYYY-MM-DD 初回登録：入力=〇〇 / スキル版=research x.y / 検証=全項目✅
- YYYY-MM-DD 再検証：〇〇のルールを適用 / 直した箇所=…
- YYYY-MM-DD 追記：引用ページを追加（@ページ名）
```

時系列で足す。過去の行は消さない・変えない。プロパティだけの変更も書く。

## 検証

| 段階 | 確かめること |
| --- | --- |
| Step1 書誌の照合 | タイトル（つづり・記号まで）、形態、雑誌名・サイト名、発行年、URL（DOI優先）、要約に原文に無い主張や数値の違いが無いか、引用ページ、著者のつづりと人数、アイコン |
| Step2 数値と固有名詞 | 統計値・p値・単位・度数・割合・年を原文と1字ずつ。品種名・試薬名・地名・人名・機関名のつづり。表にした数値と原文の図表 |
| Step3 翻訳と解釈 | 主張を歪めていないか、訳語が分野の慣例に合うか、「実務への示唆」が著者の主張を超えていないか、原典に無い知識や利用者の事情が混ざっていないか、推測にその旨が書いてあるか |
| Step4 整合 | プロパティの「要約」と本文の要約が食い違わないか、構造化ノートと要約が合っているか、注釈で「取れなかった」とした項目が空になっているか |

書誌だけの登録では Step1 だけを行う。

```
--- 検証結果 ---
Step 1 書誌の照合: ✅ / ❌（理由）
Step 2 数値と固有名詞: ✅ / ❌（理由）
Step 3 翻訳と解釈: ✅ / ❌（理由）
Step 4 整合: ✅ / ❌（理由）
総合: ✅ 全項目OK / 🔄 直して再検証
```

## AIレポートの扱い（Elicit、Gemini Deep Research）

AIが検索・選別・抽出した半自動の二次資料。ふつうの論文とは分けて扱う。

- **見分け方**：PDFに Elicit／Gemini Deep Research の表記がある、検索方法の節や流れの図（初期ヒット→要旨で選別→全文で選別→最終抽出）がある、複数の論文を合成して要約している
- **プロパティ**：形態＝調査報告書。雑誌名＝`Elicit` か `Gemini Deep Research`。発行年＝レポートを作った年（推定したら注釈に書く）。著者＝空。URL＝共有URL。タイトル＝原題＋日本語の補足（bibliography.md の5）。要約＝1項目目に選別の数（n=初期→要旨→全文→最終）、2〜4項目目に主な結論
- **本文**：3つのトグル
  - AI日本語要約：レポートの性格（ツールと母集団、リサーチクエスチョンの原文、要旨だけか全文かの比率）、検索と選別の数、抽出研究の整理（テーマ・まとまり別）、方法の要点、うまくいった条件・いかなかった条件（書いてあれば）
  - 出典・書誌事項：種別、母集団、範囲、選別の数、ページ構成、抽出列の名前、引用論文の一覧（DOI付き、主なもの優先）。DBに登録済みの論文はメンションでつなぐ
  - 登録ログ
- **信頼度の印**：レポート本体に書かれたこと（選別の数・範囲・テーマ）は印なし。個々の引用論文の細部（要旨だけ、AIの抽出経由で原文未確認）は 🟡。開けない・DOIが無い・原文が無いものは 🔴
- **検証の追加**：Step5＝レポート自体の重複に加えて、中の引用論文でDBに登録済みのものを探してメンションでつなぐ。Step6＝形態と雑誌名の選択肢の整合
- **引用論文は個別に登録しない**（数十〜数百件になるため）。個別に登録したい論文があれば、別にふつうの登録をする
- **確認**：Elicit か Gemini か。同じか近い範囲のAIレポートがすでにあれば、A 既存を再検証／B 削除して再登録／C 別の範囲として新規／D 今回は見送り、から選んでもらう
