# 検証の共通ルール

検証系のスキルは、どれもこの規律と出力の形に従う。各スキルには固有の手順だけを書き、ここにある条項は書き直さない。

## 1. 規律（12条）

1. **立証責任は主張の側にある**：明示的な裏付けが確認できない限り ✅ にしない。「もっともらしい」「一般論として正しそう」は合格の理由にならない。迷ったら 🟡
2. **AI自身の一般知識で補わない**：根拠は各スキルが決めた許容ソースだけ
3. **1主張＝1事実（atomic claim）**：複合文・表のセル・箇条書きの項目・括弧内の列挙は分解する。「A、B、C、Dを反映」は4件
4. **自分が書いた文を疑う**：対象のページはAIが過去に書いた可能性がある。「自然に読める」「自分ならこう書く」を根拠にしない。逐語で確かめる
5. **自動で書き換えない**：検証スキルは指摘と修正案を出すまで。書き換えは、利用者の承認のあとに page-review（または利用者の明示の指示）でまとめて行う
6. **止まらずに走り切る**：各段階の終わりは1行の要約だけ出し、承認を待たずに次へ進む。止まるのは致命的なエラーと入力不備、それに最終レポートでの承認だけ
7. **出力の形をそろえる**：下の2に従う
8. **優先度を必ず付ける**：🔴 必須／🟠 推奨／🟡 参考
9. **承認の選択肢は4つ**：「修正案を適用」「別案を提示」「スキップ（保留）」「却下（現状維持）」。自由記入も受ける。質問ツール（Claude の AskUserQuestion、Notion AI の ask-survey など）があればそれで聞く
10. **書き換えは1か所でまとめて**：複数の検証を同時に走らせるときも、ページを書き換えるのは page-review だけ。競合と巻き戻しを防ぐ
11. **網羅したと宣言する**：一覧を作り終えたら「カテゴリ別に全N件を検証した」と書く。件数を省かない
12. **検証の限界を書く**：開けなかった資料、原文が無いもの、解釈を保留したものを付録に書く

## 2. 出力の形

### 指摘1件の形

| 項目 | 中身 |
| --- | --- |
| ID | スキルごとの頭文字＋連番。CC（参考文献照合）、SC（科学的主張）、LC（論理整合）、EP（誤りパターン）、RI（文献ページ点検）、FI（最終整合） |
| 優先度 | 🔴／🟠／🟡 |
| 位置 | 節の名前＋（表なら何行目×何列目、箇条書きなら何番目） |
| 原文 | 逐語。置換の検索文字列にそのまま使える完全一致 |
| 判定理由 | 許容ソースとの違い、矛盾の場所、当てはまったパターンを具体的に |
| 修正案 | before/after を2〜3通り |

### 優先度の基準

- 🔴 必須：明確な誤り・矛盾・出典の無い断言・致命的な抜け・範囲外への帰属・参照切れ
- 🟠 推奨：一部だけ支持・要修正・大きな逸脱・章レベルの構造の問題
- 🟡 参考：確認できない・解釈を保留・小さな改善

### 修正案の型

削除／弱める（断言→可能性、具体的な引用→一般論）／正しい記述に直して裏付けを足す／構造を変える（表の列を足す・分け方を作り直す）。スキルごとに名前を変えてよい。

### 最終レポートの形

1. 冒頭の要約：`🔴N / 🟠N / 🟡N / ✅N`
2. 🔴と🟠を1件ずつ提示し、承認の4択で聞く
3. 🟡と✅は件数と1行要約だけ。ID一覧は折りたたみに入れる
4. 付録（折りたたみ）：検証の限界、網羅の宣言、登録し直す候補の文献など

途中の段階の要約は1行：`Phase N 完了：✅30 / 🟡15 / ❌5 / ⚪2`

## 3. 主張を外の証拠と照らす検証の共通の流れ

citation-check（引用のある主張）と fact-check（引用の無い科学的な主張）は、前処理と出力が同じで、違うのは「許容ソース」と「判定の表」だけ。

| 段階 | すること |
| --- | --- |
| 1 主張の一覧 | 対象の主張を atomic claim で全件書き出す。文献ごと（または分野ごと）の件数表を作り、取りこぼしを見直す |
| 2 ソースの割り当て | 参考文献DB `references` の登録状況と品質を見る。足りない文献は reference-registration で登録してよいか利用者に聞く |
| 2.5 範囲の照合 | 文献の目的・対象・対象外・目次を先に抜き出し、範囲の外に帰属させた主張をまとめて見つける |
| 3 照合 | 各スキルの判定の表に従う。✅候補も反証を探す（範囲・主眼・ほかの記述との矛盾） |
| 4 修正案 | 書き換えない。案だけ出す |
| 5 最終レポート | 上の2の形 |

## 4. 実行の記録

接続表に `ai_run_log`（AIの実行記録）があれば、検証のたびに1件書く。

- タイトル：`[ページ検証] 対象ページ名 - 実行日時`
- 状況：要確認（🔴あり）／情報（指摘なし）／エラー（失敗）
- 中身：対象ページ、使った検証スキル、指摘の件数（🔴／🟠／🟡）、かかった時間

## 5. 書誌のルール

文献の登録と点検は `references/bibliography.md` の書誌ルールに従う。
