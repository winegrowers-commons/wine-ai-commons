# 総力調査

関係しそうな情報を、手元のデータ、国内の事例、海外の事例、研究から集められるだけ集め、そのうえで判断や回答を出す。時間がかかってよい。

science-research との違い：science-research は一次資料に絞って事実を確かめる。総力調査は、現場の事例・実践の記録・行政資料・業界資料まで広く集め、どの情報にも信頼度を付けて区別する。

## 1. 問いを分ける（最初の1分）

- 何を判断・回答するかを1文にする
- 判断に効く論点を3〜8個に分ける（例：費用、効果、リスク、法令・補助金、先行事例、代わりの案）
- 論点ごとに、どこに答えがありそうか（手元／国内／海外／研究）を割り当てる
- 前提があいまいでも止まらない。いちばん妥当な読みで進め、確認は途中の結果と一緒にする（core の when-to-ask）
- 論点が多ければタスクの一覧を作る

## 2. 手元の情報を全部当たる

使えるものは全部使う。関係なさそうでも一度は探す。

- メモリ、プロジェクトの資料、過去のチャット
- Notion（関係するDBやページは中まで読む）、`references`
- Google Drive・Docs・Sheets、Gmail、カレンダー
- 会計（お金・取引が絡む問いのとき）
- 各自が持つ専門書PDF（専門的な問いのとき）
- 要るデータの置き場にコネクタが無ければ、コネクタのディレクトリを探して提案する

## 3. 検索の言葉を設計する

- 同義語・学名・略称・関連する概念を洗い出す
- ワイン・醸造用ブドウの話題なら、英語・フランス語・イタリア語・ドイツ語・スペイン語・ポルトガル語にも広げる（例：除葉 → leaf removal／effeuillage／defogliatura／Entblätterung／deshojado／desfolha）
- 使った言葉の一覧を回答の付録に書く

## 4. 国内の事例（日本語）

- 言い方と角度を変えて何度も探す。地名・品種・制度名など具体的な語を入れる
- 優先：省庁・自治体、農研機構・都道府県の試験場・大学、J-STAGE、業界団体、生産者本人の発信、新聞・業界紙
- 寒冷地・小規模の生産者の事例は特に探す（自分の地域条件は 🧭 AI設定ページから読む）
- コマンドで取れないサイトはブラウザで開く

## 5. 海外の事例

- 英語と、テーマによっては産地の言語で探す
- 寒冷地の産地（カナダ、ニューヨーク州、英国、ドイツ、北欧、ニュージーランド南島など）を意識して探す
- 研究は OpenAlex、Consensus、Elicit、PubMed。普及機関（大学のエクステンション、AWRI など）の実務資料も入れる

## 6. 信頼度の順に探し、原典で確かめる

上の段から探し、十分に集まれば下の段は省いてよい。

| 段 | 情報源 |
| --- | --- |
| 1 | 査読付き論文、政府・公的機関（OIV、農水省、EU規則など）、国際規格（ISO、Codex など） |
| 2 | 大学・公的研究機関の技術報告・紀要、業界団体の公式資料 |
| 3 | 専門メディア、著名な専門家の著作・講演資料、生産者本人の記録 |
| 4 | 一般のニュース、個人ブログ・フォーラム・SNS（1〜3で足りないときだけ） |

- 検索結果の要約だけで判断しない。数字・制度・結論は元のページやPDFを開いて確かめる
- 科学的な知見は新しい文献を優先し、古いものは「当時の知見」として扱う。制度の起源などは原典を優先
- 孫引きは原則使わない。原著が確かめられないときだけ「二次情報」と明記して使う
- **反対の意見と失敗した事例を、別に検索して探す。** 賛成の材料だけ集めて終わらない
- 打ち切りの目安：信頼できる情報源3件以上が一致 →「確定」。2回探して見つからない →「該当情報なし」と書いて次へ。1件だけ →「単一情報源」と付ける
- 集め終わりの目安：同じ話ばかり出るようになったら。量の目安は、Web検索20回以上、元の資料を10件以上開く

## 7. 整理して判断する

各情報に信頼度を付ける：**A**＝一次資料・公的機関・査読論文／**B**＝専門家・業界団体・生産者本人の記録／**C**＝報道・ブログ・伝聞。

回答の形（結論から）：

1. 結論・判断と、その確からしさ（高・中・低）と理由
2. 根拠にした主な事例（誰が・どこで・何をして・どうなったか・信頼度・出典）
3. 食い違う点、反対の事例（両論を並べ、信頼度の高い方を示す）
4. 利用者の状況（寒冷地、規模、手元のデータ）に当てはめるとどうなるか
5. まだ分からないこと、次に確かめるなら何か
6. 調べた範囲と限界（言語、使ったDB、開けなかった資料、有料の壁）
7. 出典（リンク一覧。手元のNotionなども含む）

- 短く済むならチャットで答える。事例が多い・あとで見返すなら Notion のページかドキュメントにまとめ、チャットには要点だけ書く（core の writing-for-humans）
- 推測と、確かめた事実を混ぜない。推測には推測と書く

## 8. 出したあとの見直し

- 事実の照合：各事実が情報源の記述と合っているか
- 数値：年・統計・濃度などが原文と合っているか
- 論理：回答の中で食い違いが無いか
- 推測の混入：情報源に無い推測が入っていないか

誤りが見つかれば直し、直した箇所を明示する。
