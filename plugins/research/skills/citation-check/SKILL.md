# 参考文献の照合

対象ページで文献を根拠に断言している箇所を atomic claim 単位で全件書き出し、原典と照らす。推測・捏造・言い過ぎ・誤引用・範囲外への帰属を見つけて、修正案を出す。

最初に research の verification-basics を読み、規律・出力の形・「主張を外の証拠と照らす流れ」に従う。ここには、このスキルで上書きする部分だけを書く。ID は `CC-001` から。

## なぜ要るか

AIは書くとき、引いた文献の中身を読まずに「その文献ならこう書いてあるだろう」と節名・数値・用語を書き込むことがある。見逃しやすいのは次のとき。

1. 表の参照列に作られた節名が並び、1〜2件にまとめられて素通りする
2. 「A、B、C、Dを反映」の複合文の中の個々の主張が埋もれる
3. AI要約の大まかな記述（「〇〇は官能評価を包括的に扱う」）を根拠に、具体的な節名や数値を✅にしてしまう
4. 文献の範囲（例：欠陥の評価が主眼で、コンクールは対象外）に反する帰属を見逃す
5. AIが過去に自分で書いた内容を「もっともらしい」と通す

## 入力

- 必須：対象ページ1件
- 任意：対象の節、除外する文献、PDFを読み直す指示

## 1. 主張の一覧

次をすべて主張として書き出す：文献の明示的な引用（「〜によれば」「X（2020）は」）、規格番号による裏付け、数値・割合・年の出典、文献ページへのメンションのある記述、暗黙の権威づけ（「標準手法である」）、**表のセルだけに入っている文献・節名の参照**、箇条書きの中の文献の参照。

文献ごとの件数表を作って「この文献の引用 N 箇所を全部挙げた」と宣言し、ページを読み直して取りこぼしを確かめる。各主張に、位置・参照文献・PDFでの確認が要るか（数値と固有名なら要る）を付ける。

## 2. 文献の登録状況と品質

`references` で登録済みかを探す。登録済みなら、登録ログがあるか、アンカーなど原典に基づく印があるかも見る。

- 品質OK → 次へ
- 品質不足（登録ログが無い、原典に基づく印が無い）→「作り直し候補」として記録し、今ある内容とPDFで照合を続ける
- 未登録 → 登録してよいか聞き、了承されたら reference-registration で登録する（本文の取れるものだけ）
- 書誌だけの登録 → 照合を飛ばして ⚪

## 2.5 範囲の照合（必須）

文献ごとに、目的、対象範囲（特に「対象外」と書かれたもの）、目次、主眼を抜き出す。範囲の外に帰属させた主張はこの時点で ❌ 候補。具体的な節名・節番号を含む主張のために目次を控えておく。

## 3. 照合

**判定の表（このスキル固有）**

| 主張の種類 | ✅に必要なもの | 見るもの |
| --- | --- | --- |
| 定量（数値・%・温度・段階数） | 原典PDFに同じ数値がある（逐語） | PDF必須 |
| 固有名（節名・節番号・原語の用語） | 原典に同じ文字列がある | PDF必須 |
| 定性（傾向・一般的な説明） | AI要約か原典に明示の裏付け | AI要約でも可 |
| 範囲 | 2.5で範囲内と判定済み | AI要約＋原典冒頭の範囲の記述 |

**数値と固有名は、AI要約だけでは✅にしない。** PDFで逐語確認できなければ 🟡 か ❌。

**❌候補のチェックリスト**（1つでも当たれば❌候補。PDFで反証できなければ確定）

- [ ] 節名・節番号が原典の目次にあるか
- [ ] 数値が原典に同じ値・同じ単位であるか
- [ ] 原語・専門用語が原典にそのまま使われているか
- [ ] 文献の範囲内か
- [ ] 複数の要素を一度に主張していないか（分解し直す）
- [ ] AI要約が「一般に扱う」程度なのに、主張が「詳しく規定」と言い過ぎていないか
- [ ] 「標準」「規格」などの権威づけが、文献の範囲内で使われているか

✅候補にも反証を探す（範囲・主眼・目次に無い節名）。AI要約とPDFが食い違えばPDFを優先。

## 4. 修正案（書き換えない）

問題の種類：推測で補った／言い過ぎ／数値の誤り・出典なし／節名・節番号の捏造／文献の取り違え／範囲外への帰属／出典の無い断言／複合文の未分解。

直し方は3つ：**削除**／**弱める**（断言→可能性、具体的な引用→一般論、出典を外す）／**別の裏付け**（別の登録済み文献、または登録すべき文献を示す。その文献の要約と照らしたことを書く）。

## 5. 最終レポート

verification-basics の形。付録に加えるもの：文献ごとの範囲の要約、新しく登録した文献、**作り直し・点検の候補になる文献ページ**（登録ログが無い、必須項目が空、ノートの構成ずれ、アンカーが原文に見つからない、重複）。単独で使ったときは一覧を出すだけで、reference-inspection の起動は利用者に任せる。

## しないこと

- 文献名だけ見て中身を推測する
- AI要約の大まかな記述で数値・固有名を✅にする
- 表のセルや箇条書きの引用を本文とまとめて見逃す
- 範囲外への帰属を「文献がその分野に触れているから」で通す
- 書誌だけの文献を検証済みとして扱う
- PDFを毎回むだに読み直す（ただし数値・固有名の確認は省かない）
