# ページの総合検証

対象ページを、文献の整備と複数の検証に分けて各スキルに振り、結果をまとめて利用者に見せ、承認された修正だけを書き込む。**ページを書き換えるのはこのスキルだけ。** 判定は各スキルのルールに任せ、ここで上書きしない。

最初に research の verification-basics を読み、規律と出力の形に従う。

## 呼ぶスキル

| 担当 | スキル | 見るもの |
| --- | --- | --- |
| A | citation-check | 出典の付いた主張 |
| B | fact-check（醸造・栽培なら error-patterns も） | 出典の無い科学的な記述 |
| C | logic-check | ページ内の食い違い |
| D | core の writing-for-humans | 表記・文体・章の中の小さな構成 |
| E | core の structure-reading → writing-for-humans | 章より大きな構成（中心の主張、並び、トグル・サブページへの出し入れ） |
| 道具 | reference-registration／reference-inspection | 文献の新規登録・作り直し・点検 |

## 原則

1. ページの記述を A／B／C に漏れなく振る。どこにも入らないものは「対象外」と書く
2. 止まるのは承認の3点だけ（中間1：主張の修正、中間2：構成の変更、最終：論理と文体）。ほかは1行の要約で走り切る
3. 骨組みから細部へ：主張の修正 → 構成 → 論理 → 文体 の順を守る
4. 各スキルの細かい出力は飲み込み、利用者には3つのレポートだけを見せる
5. 書き換えは、承認で「修正案を適用」か「別案を提示」が選ばれたものだけ

## 入力

- 必須：対象ページ1件
- 必須：読み手（誰が読むか／読み終えて何ができるようになるか／知識の水準／ふだん使う言葉）。分からなければ最初に聞く
- 既定：サブページも全部対象
- 任意：対象の節、飛ばすスキル、意図した非対称、構成を変えない部分

## 流れ

1. **読み手・範囲・やり方を決める**：サブページを洗い出す。やり方を選んでもらう
   - **作り直し**：今の中身を素材として横に置き、中心の主張から組み直す。大きな書き換えを許す
   - **少しずつ直す**：今の構成を保ち、最小限だけ直す
2. **文献の整備**：ページの文献を抜き出し、開けるか・信頼できるかを見て、採用／削除候補／重要だがWebで未確認／新規登録候補に仮に分ける（中間1で見せる）
3. **事前の見立て**：どのスキルが要るか、どれを飛ばせるかを決める（文献が無ければAは飛ばす、技術ページでなければ error-patterns は飛ばす、など）
4. **振り分け**：記述を A（出典あり）／B（出典なしの科学的記述）／C（論理）に振る。複数に当たれば両方に入れる
5. **A と B を走らせる**（互いに独立なので並行してよい）
6. **中間レポート1【承認1】**：A・Bの結果をまとめ、優先度を付けて見せる。🔴🟠を1件ずつ4択で聞く。文献の整備の結果も一緒に見せる
7. **主張の修正を書き込む**：承認されたものだけ。未登録の文献の登録や品質不足の文献の点検は reference-registration／reference-inspection に渡す
8. **E 構成**：structure-reading で中心の主張と要素の関係を読み、writing-for-humans の形で章の並べ替え・統合・分割・トグル化・サブページへの切り出しを案にする。作り直しのときは、まず3〜10行の筋書きを作り、中間2の冒頭でその承認を取ってから章ごとの案を作る。サブページにも同じことをする
9. **中間レポート2【承認2】**：構成の案を1件ずつ聞く
10. **構成の変更を書き込む**：作り直しのときは、同じ概念の説明を正本の1か所に集め、ほかを参照（メンション・同期ブロック）に変える
11. **C 論理**（構成を変えたあとの参照関係も含めて）
12. **D 文体**
13. **最終レポート【承認3】**：C と D をまとめて、🔴🟠を1件ずつ聞き、承認されたものを書き込む
14. **最終の整合チェック**：書き換えたことで起きたずれ（参照のずれ、用語の不一致、表のセルのずれ、サブページへの誤った誘導、消した重複の復活、引用位置のずれ、直したはずの未反映）を探す。見つかれば追加で聞く
15. **記録**：verification-basics の4に従い `ai_run_log` に書く。見つかった新しい誤りのパターンは error-patterns への提案候補として残す
16. **完了報告**：使ったスキル、書き込んだ件数、追加で見つかった件数、かかった時間、記録へのリンク

## 削除の依頼を受けたとき

reference-inspection から「削除（DBと引用先の両方から）」が渡されたら、引用先のページから参照を外す案と、文献ページを消す案を並べて承認を取る。文献ページの削除は戻せないので、Notion の画面で利用者が行うよう案内する（コモンズの入口には消す道具が無い）。
